# Task Context Rules

Each task must be understandable without rereading the entire project history.

Include:
- feature goal relevant to this task;
- direct dependencies;
- authoritative spec/ADR paths;
- files/modules expected to change;
- explicit non-scope;
- observable acceptance criteria;
- focused verification commands;
- migration/order constraints when relevant.

Do not paste entire PRDs or TechSpecs into task files. Link them and summarize only task-relevant constraints.
